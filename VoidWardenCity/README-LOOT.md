# VoidWardenCity 1.5.0: лут и безопасность сундуков

- Для ванильного лута используются серверные таблицы `minecraft:chests/ancient_city` и `minecraft:chests/ancient_city_ice_box`. Их содержимое, уровни чар и состав зависят от версии сервера и datapack; это таблицы сервера, а не доказанное совпадение со всеми версиями клиента Bedrock.
- `/wcity loot` — как раньше, дополнительные предметы с их метаданными. `/wcity chances` — список лута, переход по страницам, выбор предмета, кнопки −10/−5/−1/+1/+5/+10. У предметов из `/wcity loot` индивидуальный шанс, ранее сохранённый общий шанс остаётся значением по умолчанию. Идентичные предметы с одинаковым количеством имеют общий шанс; при изменении предмета или количества его настройка считается новой.
- Для ванильных предметов настройка означает вероятность **оставить уже выбранный серверной таблицей предмет**, а не абсолютный шанс предмета в сундуке. 100% сохраняет штатный шанс. Уменьшение снижает его; сверх ванильного шанса эта настройка увеличить не может. Старые строки из `chests.loot` и прежние настройки шансов остаются дополнительными наградами, могут повторять ванильные предметы. Предметы из пользовательского списка и старых настроек не удаляются.
- Автоматически обнаруживаются только одиночные, ещё не открытые сундуки с таблицей обычного Древнего города/ледника и явно помеченные сундуки. `/wcity chest` создаёт помеченный сундук, а `/wcity chestadd` регистрирует одиночный сундук, на который админ смотрит (сразу содержимое не стирает). Двойные сундуки не обслуживаются, чтобы соединённые с обычным игроковым сундуком контейнеры не очищались.
- Старая версия считала любой сундук в радиусе ивентовым. После обновления ранее обработанные сундуки уже утратили ванильную таблицу: отличить настоящий ивентовый от пользовательского по прежним координатам нельзя. Поэтому они не регистрируются автоматически. Для каждого настоящего старого сундука администратор использует `/wcity chestadd`, а для немеченых новых природных сундуков обнаружение автоматическое.
- Сохраните папку `plugins/VoidWardenCity/`; JAR обновление не заменяет настройки, `points.yml`, `loot-items.yml`, `loot-chances.yml`, `chests.yml`. Только полный перезапуск. Сначала проверять на тестовом сервере, особенно открытие, перезапуск, добавление предметов, повторное заполнение, одиночные/двойные сундуки, защиту и команды. Командные награды из `chests.loot` работают как прежде: при фоновом обновлении без открывающего игрока не выполняются.
