# Перенос VoidPE на PowerNukkitX: подготовка

Исходная точка: `94f74f5` ветки `arena/41da8305-geyserplugins`. Старые проекты, ресурспаки и маппинги не изменены. `PowerNukkitX-beta.zip`, `WorldEdit-version-7.4.x.zip` и `WorldGuard-version-7.0.x.zip` — оригинальные архивы пользователя.

## Найдено в исходном коде PNX

- Пространство имён API — `org.powernukkitx`, а не Bukkit/Paper. Сборка PNX настроена на Java 25. Не следует считать Bukkit JAR совместимыми с PNX.
- `NetworkConstants.CODEC` использует `Bedrock_v2225`; `RequestNetworkSettingsHandler` и `LoginHandler` отклоняют несовпадающий протокол. README этого архива указывает Bedrock 26.60. Поддержка старых 1.21.x из коробки не подтверждается и потребует отдельного решения и проверки протоколов, блоков и предметов.
- `inventory.fake.FakeInventory` и `FakeInventoryType` содержат CHEST и DOUBLE_CHEST, обработчики предметов и закрытия. Это основание для реализации инвентарных меню на Bedrock, но работа с пользовательскими предметами, защита от дюпов и закрытие при отключении/ошибке требуют отдельных тестов. Обычные формы применять там, где они не ухудшают функциональность.
- Реализованы загрузка resource pack (`ZippedResourcePackLoader` принимает zip и mcpack) и API custom items. Маппинги Geyser нельзя автоматически считать маппингами PNX; ресурспаки нужно проверять по составу, приоритетам и ID в реальном клиенте.
- В предоставленных деревьях WorldEdit и WorldGuard нет готового модуля PNX. Их API, адаптер мира/игрока/команд/прав и события защиты требуют отдельного порта; простая перекомпиляция Bukkit-модуля не подходит. Сохранять исходные лицензии и авторство.

## Порядок работ

1. Зафиксировать целевые версии Bedrock и правила переноса миров, идентификаторов, инвентарей, регионов, кланов и прав. Остановить сервер и сделать независимый бэкап всех миров и данных, проверить его восстановление.
2. Поднять точную сборку PNX из предоставленного архива на отдельном тестовом сервере, зафиксировать сборку, доступные API и тестовый клиент. Старый сервер не менять.
3. Реализовать и протестировать платформенный слой: идентичность Bedrock, права, события, предметы, GUI и экономика. Не включать опасные несовместимые плагины без эквивалента API.
4. Переносить плагины в отдельные проекты PNX с тестами и миграцией данных; инвентарные GUI — FakeInventory, не заменяя нужные инвентарные операции формами. Сверять команды, права, награды, автопак и конфиги.
5. WorldEdit и WorldGuard — отдельные проекты с адаптерами PNX; проверить совместимость защиты, флагов, сохранения регионов, редактирования блоков и зависимостей наших плагинов. Не отключать защиту при ошибке.
6. Переносить предметы, маппинги и паки после установления формата PNX; проверять внешний вид, метаданные, стаки, крафт, инвентари и переподключение Bedrock. Аудио автопак VoidGifts сохранить.
7. Проверить на тестовом сервере с реальными клиентами, в том числе рестарт/перенос данных, многопользовательские операции, дюпы и нагрузку. Только после этого выдавать конкретные готовые сборки и инструкции установки.

## Текущий статус

Подготовлены только анализ и архив бэкапа файлов репозитория. Ни один плагин, WorldEdit, WorldGuard, маппинг или ресурспак ещё не перенесён на PNX и не проверен в игре. Бэкап репозитория не заменяет отдельного бэкапа работающего сервера.
