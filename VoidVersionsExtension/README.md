# VoidVersionsExtension

Расширение для **GeyserMC**, которое расширяет диапазон принимаемых версий
Minecraft: Bedrock — от **1.20** до самой новой, что поддерживает установленный
Geyser (сейчас 26.52).

## Зачем

Стоковый Geyser принимает только несколько свежих версий Bedrock
(сейчас — 26.30–26.52). Все, у кого клиент старше (не обновился, старый
телефон, пиратка со старым apk и т.п.), получают «Unsupported version»
ещё на рукопожатии. При этом библиотека протоколов cloudburst, на которой
построен Geyser, содержит кодеки всех версий Bedrock — Geyser просто не
регистрирует старые.

## Как работает

При инициализации Geyser (событие `GeyserPreInitializeEvent`, то есть до
приёма подключений) расширение:

1. Сканирует classpath на классы кодеков cloudburst
   `org.cloudburstmc.protocol.bedrock.codec.v<протокол>.Bedrock_v<протокол>`.
2. Отбрасывает уже поддержанные Geyser нативно, отключённые в конфиге
   и те, чья версия Minecraft ниже `min-version` (по умолчанию 1.20.0).
3. Прогоняет каждый кодек через штатный `CodecProcessor.processCodec`
   Geyser — те же «санитарные» правки сериализаторов, что и у родных версий.
4. Регистрирует кодеки в списках `GameProtocol`
   (`SUPPORTED_BEDROCK_CODECS`, `SUPPORTED_BEDROCK_PROTOCOLS`,
   `SUPPORTED_BEDROCK_VERSIONS`) с сохранением порядка по протоколу.

Единственная проверка версии в Geyser — `UpstreamPacketHandler` →
`GameProtocol.getBedrockCodec(protocol)` — после этого пропускает старые
клиенты, и сессия работает на кодеке своей версии (сериализация пакетов
под старую версию — забота cloudburst, как и у нативно поддержанных версий).

Ядро Geyser дёргается только рефлексией: расширение компилируется против
Geyser API и ставится на любой актуальный Geyser. Если что-то пойдёт не так,
Geyser продолжит работу со стандартным диапазоном — расширение не может
уронить сервер, оно напишет в лог, что не получилось.

## Установка

1. Положить `VoidVersionsExtension-1.0.0.jar` в папку расширений Geyser:
   - Geyser-Spigot: `plugins/Geyser-Spigot/extensions/`
   - Geyser Standalone: `extensions/` рядом с jar Geyser.
2. Перезапустить сервер.
3. В консоли при старте должно появиться:
   `VoidVersions: теперь принимаются клиенты: 1.20.0 (протокол 589), ...`

## Настройки

Файл `config.properties` появится при первом запуске в папке данных
расширения (`plugins/Geyser-Spigot/extensions/voidversions/`):

| Ключ | По умолчанию | Что значит |
| --- | --- | --- |
| `enabled` | `true` | Полностью выключить расширение |
| `min-version` | `1.20.0` | Самая старая добавляемая версия Minecraft |
| `scan-from-protocol` | `560` | Начало диапазона поиска кодеков |
| `scan-to-protocol` | `2500` | Конец диапазона поиска кодеков |
| `disabled-protocols` | — | Протоколы-исключения через запятую |
| `verbose` | `false` | Подробный лог по каждой версии |

## Честные ограничения

Расширение открывает **вход**, но не переписывает игровой процесс под
старые клиенты:

- Чем старше клиент, тем больше визуальных глюков: новые блоки/предметы/
  сущности, которых не было в его версии, могут отображаться неправильно
  или не отображаться. Играбельно, но не идеально — как и предупреждает
  сама вики Geyser про старые версии.
- Инвентарь: серверно-авторитетный инвентарь появился в Bedrock позже 1.20,
  поэтому на клиентах 1.20 возможны рассинхроны инвентаря в редких случаях.
- Античиты (включая VoidAntiCheat) могут чаще срабатывать на очень старых
  клиентах — движение там предсказывается сервером по данным новой версии.
- Старые клиенты подключаются по RakNet (как обычно); NetherNet-транспорт
  Geyser касается только 26.50+ и старых клиентов не затрагивает.

## Сборка

```bash
./gradlew build
```

Готовый jar: `build/libs/VoidVersionsExtension-1.0.0.jar`.
