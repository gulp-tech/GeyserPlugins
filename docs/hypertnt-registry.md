# HyperTNT 2.1.0 — персистентный реестр установленного TNT

## Зачем

До 2.1.0 тип установленного кастомного TNT хранился только в памяти
(`Map<Location, String>` в `TntListener`) и терялся при перезапуске сервера.
Реестр `{UUID мира, x, y, z → тип TNT}` теперь сохраняется на диск и
восстанавливается — установка, слом, поджог, взрывы, поршни и замена блоками
других плагинов корректно обновляют записи.

## Файл данных

`plugins/HyperTNT/placed-tnts.txt` — одна запись на строку:

```
worldUUID;x;y;z;tnt_type
```

- каждое изменение сохраняется сразу (атомарная замена файла: tmp + move);
- повреждённые строки пропускаются с предупреждением в консоль;
- устаревшие записи (блок больше не TNT) удаляются при загрузке чанка;
- потерянные после старых версий типы **не угадываются** — записей нет, блок
  остаётся ванильным.

## Семантика

| Событие | Действие с реестром |
|---|---|
| Установка кастомного TNT | запись ставится/заменяется |
| Установка любого другого блока на координаты записи | запись снимается (обычный TNT не становится кастомным) |
| Слом (не отменён) | запись снимается, падает кастомный предмет |
| Поджог (BlockBurnEvent) | запись снимается |
| Поджог огнём/диспенсером (BlockIgniteEvent) | подрыв своим типом вместо ванильного |
| Лава касается TNT (BlockFromToEvent) | подрыв своим типом |
| Взрыв (Entity/BlockExplodeEvent) | записанный TNT в списке разрушаемых подрывается своим типом (цепные взрывы сохраняют тип) |
| Кастомный взрыв (ExplosionService) | у разрушенных блоков записи снимаются; кастомный TNT вместо ванильного дропа роняет свой предмет |
| Поршни (extend/retract) | записи едут вместе с блоками (вдоль `getDirection()`) |
| Загрузка чанка | не-TNT блоки по записям удаляют записи |

## Ограничения

- Замена блоков «в обход событий» (WorldEdit с отключёнными событиями, правка
  мира оффлайн-инструментами без событий) может оставить запись без блока —
  такая запись удаляется при загрузке чанка, но между событиями возможны ложные
  срабатывания. Полное устранение требует поддержки per-block display в ядре
  Purpurbedrock (задача ядра).
- Реестр не привязан к несуществующему API ядра: интеграция
  `{мир, координаты → тип}` с серверным интерфейсом ядра согласуется отдельно.

## Проверка

- Юнит-тест: `HyperTNT/src/testSelf/java/mk/hypertnt/TntRegistryTest.java`
  (гоняется CI шагом «Проверить и собрать плагин HyperTNT»).
- Ручная проверка на копии сервера: установка → перезапуск → тип сохраняется;
  обычный TNT на старых координатах остаётся обычным; цепной взрыв, поршни,
  поджог и лава не теряют тип; `placed-tnts.txt` соответствует реальности.
