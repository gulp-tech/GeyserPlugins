# VoidCommandsExtension 1.0.0

Расширение Geyser-Spigot для VoidPE: показывает Bedrock-игроку варианты аргументов из настоящих Bukkit/Paper tab-completer’ов. Например, для `/home ` используются дома именно этого игрока, возвращённые EssentialsX; `/sethome`, `/warp`, `/clan`, `/wcity` и другие команды обрабатываются тем же общим механизмом, без отдельного списка названий домов или команд.

## Установка

1. Оставьте в `plugins/Geyser-Spigot/config.yml` `command-suggestions: true`.
2. Положите `VoidCommandsExtension-1.0.0.jar` в `plugins/Geyser-Spigot/extensions/`.
3. Полностью перезапустите Purpur. TAB заменять не требуется.
4. Для скрытия красных чисел скорборда также замените `VoidResourcePack.mcpack` в `plugins/Geyser-Spigot/packs/` на версию 1.18.0 из этого репозитория и снова перезапустите сервер.

Расширение предназначено именно для **Geyser-Spigot на одном JVM с Purpur**, поскольку вызывает `CommandMap.tabComplete` у локального игрока. На отдельном proxy без Bukkit API оно отключится с понятным сообщением и не помешает входу игроков.

## Как это работает

- Geyser преобразует Brigadier в `AvailableCommandsPacket`, но Java `ClientboundCommandSuggestionsPacket` для Bedrock не используется.
- Перед отправкой `AvailableCommandsPacket` расширение присваивает свободным строковым аргументам уникальный **per-player soft enum**. Статические Brigadier enum и типы игроков, координат, чисел и JSON не перезаписываются.
- На основном потоке Purpur вызывается `Bukkit.getCommandMap().tabComplete(player, командная_строка)`. Выполнение команды при этом не происходит.
- Результат передаётся клиенту через `UpdateSoftEnumPacket(SET)`. После любой выполненной игроком команды обновление повторяется, поэтому `/sethome новый` и `/delhome старый` меняют подсказки без перезахода. Предусмотрено и периодическое обновление внешних изменений.
- Для вложенных аргументов префикс строится из литералов и уже полученных значений конкретной overload-ветки. Неизвестные значения не выдумываются.

Bedrock не отправляет Java-запрос completion на каждое нажатие клавиши. Поэтому свежесть списка обеспечивают join, выполненная команда, смена мира и периодический refresh, а фильтрацию по уже введённым буквам выполняет клиент. Если сам плагин команды не возвращает tab-completion, расширение не может получить её из исполняемого кода команды.

## Настройка

После первого запуска создаётся `plugins/Geyser-Spigot/extensions/voidcommands/config.properties`:

- `max-depth=4` — глубина аргументов каждой ветки;
- `max-targets=1024` — общий предохранитель на число soft enums игрока;
- `max-suggestions=100` — предел значений одного аргумента;
- `params-per-tick=8` — количество completer-вызовов на основном потоке за тик;
- `refresh-after-command-ticks=2` — задержка обновления после команды;
- `periodic-refresh-ticks=6000` — фоновый refresh (0 отключает);
- `verbose=false` — подробные журналы.

После изменения конфига перезапустите сервер. Не устанавливайте большие лимиты без проверки на слабых телефонах: Bedrock может тормозить при чрезмерном количестве подсказок.
